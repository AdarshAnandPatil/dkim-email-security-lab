How does it work?
  1. Email data is collected.
  2. The browser creates a real SHA-256 digest using Web Crypto.
  3. The project visualizes the role of private-key signing without exposing a real private key.
  4. A DKIM-Signature style header is displayed.
  5. The receiver forms selector._domainkey.domain for DNS lookup.
  6. Unchanged demo content produces PASS.

Why can DKIM FAIL?
The signed message has cryptographic data associated with protected content. If an attacker modifies protected content after signing, the receiver verifies the received version and the signature may no longer match. This teaching simulation demonstrates that core concept. Real DKIM depends on signed fields, body coverage and canonicalization.

🎓 Project Information
🎯 Objective
Make DKIM easy to understand through an interactive web application, AI-style robot animation, voice narration, simulator and attack demonstration.
🧩 Modules
Home • AI Robot Demo • DKIM Simulator • DNS Visualization • PASS • Attack • FAIL • Seminar PPT.
🛠 Technologies
HTML5, CSS3, JavaScript, Web Crypto API, Web Speech API, Node.js and Express.
🔐 Security Concept
A domain-level signing system creates a signature; the receiver retrieves a public key using DNS and verifies it.
System Architecture
👤 Sender → 🤖 DKIM Signer (Private Key) → 📧 Signed Email → 🌐 Internet → 🤖 Receiver ↔ 🌐 DNS Public Key → 🔍 Verify → PASS / FAIL
Suggested Project Explanation
“Our project converts DKIM theory into an interactive demonstration. First, the audience watches AI-style robots explain the complete process with voice. Next, we enter an email into the simulator and observe hashing, a DKIM header and DNS lookup. Then we modify the message as an attacker and show why verification can fail. Finally, the interactive PPT summarizes the theory.”
